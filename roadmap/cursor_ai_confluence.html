Комплексное решение для работы с искусственным интеллектом в защищенном контуре с автоматической деперсонализацией данных согласно 152-ФЗ.

Целевая архитектура решения

Фундамент решения — двухконтурная модель обработки. Она физически разделяет «Сырой контур» (содержащий персональные данные) и «Обезличенный контур», к которому обращаются внешние ИИ-инструменты (AI). Это исключает утечку чувствительной информации за пределы периметра компании.

Контур А

Confluence (Raw)

Сырые документы, транскрипты, ПДн сотрудников.

Доступ ИИ закрыт

Сервис dp152

Анонимизация

Контур Б

Confluence (Safe)

Обезличенные копии в формате Markdown.

Принцип работы архитектуры

Любое изменение документа в "Контуре А" вызывает автоматическое событие (Webhook). Промежуточный сервис деперсонализации получает текст, удаляет ФИО, адреса и телефоны, и сохраняет результат в "Контур Б". Аналитики через Cursor AI (IDE) видят только этот очищенный контент.

Ключевые компоненты

Система состоит из трех модулей, которые работают синхронно для обеспечения безопасности и продуктивности аналитиков.

🛡️

Сервис деперсонализации (dp152)

  • • Автоматическое обнаружение персональных данных (ПДн) по 152-ФЗ.
  • • Замена имен и реквизитов на уникальные обезличенные идентификаторы (токены).
🔗

Confluence MCP Server

  • • Реализация протокола контекста модели (Model Context Protocol).
  • • Обеспечение безопасного "окна" доступа для Cursor AI только к анонимизированным данным.
💻

Шаблон Cursor (ai-project-template)

  • • Предустановленные правила взаимодействия с ИИ (.cursorrules).
  • • Встроенные инструкции по проверке документов перед обратной публикацией.

Гарантии информационной безопасности

Использование данной архитектуры снижает риск попадания ПДн во внешние модели ИИ (AI) до нуля. Все вычисления и трансформации текста происходят внутри контролируемого периметра.

Регламент взаимодействия

Процесс работы аналитика разделен на три этапа: получение контекста, разработка и публикация результата.

1

Запрос контекста

Аналитик через Cursor AI отправляет запрос: "Найди требования к модулю Х". MCP-сервер обращается к обезличенной базе Confluence и возвращает текст в Markdown.

2

Локальная разработка

ИИ помогает аналитику писать спецификации на основе полученных знаний, не имея доступа к именам реальных клиентов или сотрудников.

3

Контроль и выгрузка

Готовый документ проходит локальный линтинг (автоматическую проверку) на отсутствие утечек данных и загружается обратно в Confluence.

Интерфейс аналитика

// .cursor/mcp.json
{
  "mcpServers": {
    "confluence-safe": {
      "command": "npx",
      "args": ["@corp/mcp-confluence-bridge"]
    }
  }
}

"Контекст модели ограничен безопасным пространством (Sanitized Space). Прямой доступ к Raw Confluence заблокирован."

Дорожная карта реализации

Этап 1: Сервис dp152

Контейнеризация алгоритмов обезличивания и создание REST API (интерфейса взаимодействия) для приема текстов.

Этап 2: Конвейер Confluence

Настройка автоматической пересылки документов из Confluence в сервис деперсонализации и публикация в безопасное пространство.

Этап 3: MCP Server

Развертывание и настройка сервера протокола контекста модели для подключения Cursor AI к базе знаний.

Этап 4: Развертывание

Обновление репозиториев аналитиков, обучение персонала и запуск пилотного проекта.
