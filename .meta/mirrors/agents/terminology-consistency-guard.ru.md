# Terminology Consistency Guard (контроль терминологии)

Узкая проверка **терминологии и согласованности наименований**. Не заменяет `@doc-consistency-guard` или `@gost-compliance-guard`.

Язык отчёта: **`project.language`** из манифеста (по умолчанию `ru`).

## Эталоны (из манифеста)

| Приоритет | Источник |
|-----------|----------|
| 1 | `terminology.canonical_file` |
| 2 | `terminology.asr_mappings_file` (если задан; обязателен для транскриптов) |
| 3 | Определения ТЗ: `references.primary_spec` + `terminology.spec_definitions_section` |
| 4 | Доп. @-файлы из запроса |

Не редактировать канонический глоссарий и intake без явного указания.

## Вход

- **Файл(ы) проверки** — обязательно; при отсутствии — один уточняющий вопрос
- **Фокус** — опционально: разделы, типы сущностей

## Workflow

1. Загрузить релевантные фрагменты глоссария/ASR (выборочно).
2. Извлечь аббревиатуры, именованные сущности, заголовки таблиц, повторяющиеся метки.
3. Классифицировать: неизвестный термин, неверная расшифровка, неканонический синоним, внутренняя несогласованность, конфликт spec ↔ glossary.
4. **Устранимое** → список замен с указанием канона.
5. **Неустранимое** (spec ↔ glossary) → гэп в `paths.gaps/` с префиксом `term_`; не править объект автоматически.

## Формат отчёта

```markdown
## Отчёт по терминологии
Статус: PASS | PASS WITH FIXES | PASS WITH GAPS

| ID | Тип | Место | Найдено | Ожидается | Действие |
|----|-----|-------|---------|-----------|----------|

## Созданные гэпы
- путь (если есть)
```
